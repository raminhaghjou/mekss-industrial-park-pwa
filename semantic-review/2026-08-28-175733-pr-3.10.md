# Factory management route and migration contract tests

The change adds a PostgreSQL-backed AppModule E2E suite for factory management plus a static contract for the factory review metadata migration. It targets scoped reads, canonical creation, profile updates, review decisions, concurrent decision linearization, audit rollback, and fresh-login reads. Several assertions do not yet prove the requested contract: mutating-route role guards are largely untested, one uniqueness rollback check observes a value never submitted, and the migration checks can be satisfied by unrelated schema fields or SQL outside their narrow denylist. The migration contract passes locally, but the PostgreSQL E2E suite has not run in the available environment.

Watch for: **confirmed** missing authorization coverage on create/update/decision routes; **confirmed** vacuous national-ID conflict rollback assertion; **confirmed** unscoped Prisma schema matching; **confirmed** permissive migration SQL/type checks; **confirmed** unexecuted PostgreSQL E2E behavior.

**Verdict**: NEEDS_CHANGES

## High-level view

The E2E suite exercises AppModule over HTTP with real Prisma transactions. **Confirmed:** its role matrix reaches only the managed-list guard for non-management roles, leaving independently decorated mutation endpoints without regression coverage.

The uniqueness scenarios verify 409 responses for license and national-ID collisions. **Confirmed:** the national-ID branch queries a generated default that was replaced by the conflicting override, so its no-insert postcondition cannot detect a persisted row from that request.

The migration contract checks nullable columns, indexes, and the SET NULL foreign key. **Confirmed:** its schema expressions are not scoped to Factory, while its SQL rules allow wrong column types and destructive operations including DROP INDEX, DROP TYPE, and RENAME.

The migration contract’s three Jest cases pass, and prior validation reports successful typecheck and targeted lint. **Confirmed:** the database safety runner rejected E2E execution without `MEKSS_TEST_DATABASE=1`, so the PostgreSQL route, race, trigger, and cleanup behavior remains unobserved.

<details><summary>Details</summary>

## Independent mutation guards are outside the role matrix

The non-management-role loop at `test/factory-management.e2e-spec.ts:210-213` sends only `GET /api/v1/factories/managed`. Create, update, approve, and reject have independent route-level role declarations and can regress separately. This is a **confirmed** gap against “other role authorization”: no request proves that owner, guard, official, or employee is denied creation; that guard, official, and employee cannot update; or that owner, guard, official, and employee cannot decide a review. Add a denied-call matrix for each mutation surface and assert both status and unchanged factory/audit state.

## National-ID conflict postcondition cannot see the attempted row

At `test/factory-management.e2e-spec.ts:336-341`, the `4002` case overrides `nationalId` with `1888800001`, but the final count checks `1840020000`. That generated value was replaced before submission, making the rollback assertion **confirmed** to be vacuous for this branch. Query `licenseNumber: 'LIC-4002'` and verify no create audit was committed.

## Prisma assertions are not tied to Factory

The checks at `src/preservation/factory-review-migration.contract.spec.ts:12-17` and `:39-45` search the complete schema string. False positives are **confirmed**: `rejectionReason String?` also exists on Request and Advertisement, `id String @id @default(cuid())` appears throughout the schema, and `isApproved Boolean @default(false)` exists on User and Advertisement. Extract `model Factory` and `model User` before applying field and relation assertions.

## Additive-only SQL rules allow wrong types and destructive operations

The loop at `src/preservation/factory-review-migration.contract.spec.ts:21-24` accepts either `TEXT` or `TIMESTAMP(3)` for every field, so swapped metadata types pass. The denylist at `:34-38` rejects only selected UPDATE, INSERT, DROP, and ALTER spellings; `DROP INDEX`, `DROP TYPE`, `ALTER TABLE ... RENAME`, extra columns, and CTE-driven updates remain accepted. This **confirmed** mismatch with the additive-only claim should be closed by exact per-column types and a normalized statement whitelist, or comprehensive rejection of DROP, RENAME, and data mutation.

## PostgreSQL behavior remains unverified

The static contract passed 3/3, while prior validation reports passing typecheck and lint with only the TypeScript-version support warning. The runner stopped because `MEKSS_TEST_DATABASE=1` was unavailable, so the E2E execution gap is **confirmed**. Run `scripts/run-backend-integration.mjs` against an approved disposable PostgreSQL database to observe the concurrent race, trigger rollback, and schema cleanup.
