# Factory review metadata and closure of prior factory-management findings

This pass re-reviews Task 3.10 ("Complete factory management and approval contracts") after the `fec0f6bf` fix commit, written specifically to close the 5 confirmed issues from the prior review (`2026-08-28-175733-pr-3.10.md`): missing mutation-role-denial coverage, a vacuous national-ID rollback assertion, unscoped Prisma schema matching, a permissive migration SQL contract, and an unexecuted PostgreSQL E2E suite. The commit adds `rejectionReason`/`reviewedById`/`reviewedAt` columns and a `FactoryReviewer` relation, tightens the migration contract, rewrites the e2e role matrix, and fixes the uniqueness-rollback assertion. All 5 prior issues are verified resolved by direct inspection and, for the E2E gap, by actually running the suite against a live PostgreSQL 15 container. Watch for: **possible** minor UX gap where the frontend detail view doesn't surface the new `reviewedBy`/`reviewedAt` fields even though the API now returns them.

**Verdict**: APPROVED

## High-level view

`decideFactory` uses a single conditional `updateMany` scoped by `id + status=PENDING + isApproved=false` plus the actor's factory scope, so exactly one of a concurrent approve/reject pair can win; the audit record is written in the same transaction as the state transition, and a rollback test (trigger-forced audit failure) confirms the pending decision reverts atomically alongside unrelated audit rows staying untouched.

Authorization for factories now runs through `factoryFilter`, a single scope function shared by list, detail, create-target-validation, update, and decision paths: `SUPER_ADMIN`/`GOVERNMENT_OFFICIAL` see everything, `FACTORY_OWNER` is restricted to `managerId`, and `PARK_MANAGER`/`SECURITY_GUARD` are restricted to their managed/assigned parks. The e2e suite now exercises denial for every mutation route (create, update, approve, reject) across owner/guard/official/employee, closing the gap the prior review flagged.

The new migration only adds three nullable columns, two supporting indexes, and a `SET NULL` foreign key on `reviewedById`; the contract spec now extracts the `Factory`/`User` model blocks before asserting on them and requires an exact normalized-string match of the whole `migration.sql`, closing both the unscoped-regex and permissive-SQL findings. Applying the migration to a real Postgres 15 database and running the e2e suite against it now succeeds (7/7 tests), closing the last open finding.

The frontend factory API client maps one-to-one onto the controller's routes, and `ManageFactoriesPage` builds separate create/update payload whitelists that exclude `parkId`, `managerId`, `status`, `isApproved`, `rejectionReason`, matching the DTO's rejection of those fields on update.

## Transaction and audit integrity for the review decision

`decideFactory` re-reads the factory under scope, rejects if it isn't `PENDING`/unapproved, then performs the state transition via `updateMany` re-asserting `status: PENDING, isApproved: false` plus the caller's scope in the same `WHERE`. Only a transition with `count === 1` is accepted; the loser gets `ConflictException`. Because the audit write happens inside the same `$transaction` as the `updateMany` (via `auditedTransaction`), the rollback test that forces an audit-insert trigger failure demonstrates the state transition itself gets rolled back too — there's no window where the factory flips to `ACTIVE`/`INACTIVE` without a corresponding durable audit row.

## Frontend/backend contract alignment

Frontend routing restricts `admin/factories` to `SUPER_ADMIN`/`PARK_MANAGER`, matching the backend's `@Roles` on `/factories/managed*` and the mutation endpoints. The `reject` API call's body shape (`{ reason }`) matches `ReasonDto`.
